# Copier update 업그레이드 경로: Research Report
*Generated: 2026-07-26 | Sources: 16 | Adapters: [adapter-exa, adapter-firecrawl] | Failed: none*

## Executive Summary

`copier update`는 답변 파일(`.copier-answers.yml`)의 `_commit`을 기준점으로 "과거 상태"를 재구성해 사용자 수정분과 템플릿 변경분을 3-way merge로 합치는 알고리즘이다. 안전한 update의 3대 전제는 (1) 유효한 `.copier-answers.yml` 존재, (2) 템플릿이 git 태그로 버전 관리됨, (3) 대상 프로젝트가 git 관리 + **clean working tree**다. 충돌은 `--conflict inline`(기본, git 스타일 마커) 또는 `--conflict rej`(`.rej` 파일)로 처리하며, pre-commit 훅으로 충돌 마커 커밋을 차단하는 것이 공식 권장이다. 롤백은 별도 커맨드가 아니라 `--vcs-ref=<이전 tag>`로 지정해 다운그레이드하며, migrations는 `new ≥ 선언 version > old` 조건에서만 실행돼 다운그레이드 시 자동 실행되지 않는 점을 주의해야 한다. `.copier-answers.yml`은 **절대 수동 편집 금지**(smart-diff 파손, 비지원)이며 반드시 git tracked여야 한다.

## 1. 3-way merge 메커니즘과 충돌 해소

`copier update`는 다음 흐름으로 동작한다 ([Copier – Updating a project](https://copier.readthedocs.io/en/stable/updating/)):

1. `.copier-answers.yml`의 `_commit` 버전으로 fresh 프로젝트를 임시 디렉토리에 재생성.
2. 그 fresh 프로젝트와 현재(사용자) 프로젝트를 비교해 사용자 수정분 diff(patch) 추출.
3. pre-migrations 적용 후, 최신 템플릿 변경으로 프로젝트 업데이트.
4. 앞서 얻은 diff를 재적용(`git apply`)하고 post-migrations 실행.

**전제 조건 3가지** — 유효한 `.copier-answers.yml`, git 태그로 버전 관리된 템플릿, git 관리 대상 폴더(실행 전 `git status` clean) ([Copier – Updating](https://copier.readthedocs.io/en/stable/updating/)).

**충돌 모드 (`--conflict`)** ([Configuring – conflict](https://copier.readthedocs.io/en/stable/configuring/)):
- **`inline` (기본값)**: 파일 내부에 `<<<<<<<`/`=======`/`>>>>>>>` 마커 삽입. 공식 stable 문서가 `Default value: inline` 명시. ⚠️ 단, v7.2.0 등 구버전은 기본값이 `rej`였으므로 배포 대상 Copier 버전 확인 필요.
- **`rej`**: 충돌 파일마다 `.rej` 파일 생성, 실패한 hunk만 분리.

**충돌 마커 커밋 방지 (공식 권장)** — pre-commit 훅으로 차단 ([Copier – Preventing Commit of Merge Conflicts](https://copier.readthedocs.io/en/stable/updating/)):
- `inline`: `pre-commit-hooks`의 `check-merge-conflict` (`args: [--assume-in-merge]`).
- `rej`: `\.rej$` 파일을 fail시키는 로컬 훅.

**중단·회복** — 충돌 상태(unmerged index)에서는 `git merge --abort`·`git checkout .`이 작동하지 않는다. 회복 시퀀스는 `git reset` → `git checkout .` → `git clean -d -i` ([Copier – Aborting an update](https://copier.readthedocs.io/en/stable/updating/)). 이 시퀀스가 안전하려면 **clean tree에서 시작**해야 update 변경만 격리된다 — dirty tree면 `git checkout .`이 사용자의 미커밋 작업까지 삭제한다. 알고리즘 자체가 깨지면(외부 리소스 소실, 비호환 Jinja 확장) `copier recopy`로 폴백한다 ([Copier – Recover from a broken update](https://copier.readthedocs.io/en/stable/updating/)).

`context_lines` 파라미터는 충돌 감지 정밀도를 조절한다 — 공식 stable 기준 **기본값 1** (Git 기본 3과 다름) ([Configuring – context_lines](https://copier.readthedocs.io/en/stable/configuring/)). 값이 클수록 감지 정확·충돌 증가.

## 2. `.copier-answers.yml` — `_commit`/`_src_path`, 커밋 전략

이 파일은 사용자 답변을 저장해 향후 update를 매끄럽게 만들며, **git tracked여야 update/재구성이 동작**한다 ([Configuring a template](https://copier.readthedocs.io/en/stable/configuring/)). 템플릿 쪽에서 `{{ _copier_conf.answers_file }}.jinja`로 생성되고 내용 예시는 ([creating.md](https://github.com/copier-org/copier/blob/730009df/docs/creating.md)):

```yaml
# Changes here will be overwritten by Copier
_commit: 0.1.0
_src_path: gh:your_account/your_template
project_name: super_project
```

- **`_commit`** — 마지막 update에 쓴 템플릿 버전(git tag). update 시 "과거 상태" 재구성의 기준 ref ([DeepWiki – Updating Projects](https://deepwiki.com/copier-org/copier/3.4-updating-projects)).
- **`_src_path`** — 템플릿 출처(예: `gh:acct/tpl` 또는 로컬 경로). update가 어디서 재clone할지 결정 ([creating.md](https://github.com/copier-org/copier/blob/730009df/docs/creating.md)).

`_copier_answers` dict는 secret 답변·직렬화 불가 데이터를 제외한 안전 가공본이다 ([creating.md](https://github.com/copier-org/copier/blob/730009df/docs/creating.md); [The Blue Book](https://lyz-code.github.io/blue-book/copier/)).

**핵심 규칙: 수동 편집 절대 금지** — Copier가 "이 수정 답변이 현재 프로젝트를 생성했다"고 오인해 smart-diff가 예측 불가 동작을 하며, **비지원 경로**다 ([Copier – Never change the answers file manually](https://copier.readthedocs.io/en/stable/updating/)). 답변 변경은 정규 경로 사용:
- 전체 재답변: `copier update`
- 직전 답변 재사용: `copier update --defaults`
- 한 질문만: `copier update --defaults --data key="val"`
- 템플릿 고정, 답변만 갱신: `copier update --vcs-ref=:current:`

⚠️ **모노레포 주의 (단일 소스)** — 한 repo에 여러 템플릿을 서브디렉토리로 두면 `_src_path` 기반 update가 실패할 수 있다. Copier는 현재 "repo당 템플릿 1개"만 지원하고 `copier.yml`이 루트에 있어야 한다 ([Issue #2371](https://github.com/copier-org/copier/issues/2371)) — 이슈 트래커 논의이므로 flag. 멀티 템플릿은 답변 파일 분리(`-a .copier-answers.<name>.yml`)로 우회.

## 3. `--vcs-ref` — 버전 타겟팅과 롤백

기본 `copier update`는 모든 git 태그를 PEP 440으로 비교해 **최신 태그**를 checkout해 update한다 ([Copier – Updating](https://copier.readthedocs.io/en/stable/updating/); [Generating – Templates versions](https://copier.readthedocs.io/en/stable/generating/)). `--vcs-ref` 값은 답변 파일에 `_commit`으로 저장되며 `copier.yml`에서는 설정 불가(CLI/API 전용) ([Configuring – vcs_ref](https://copier.readthedocs.io/en/stable/configuring/)).

사용 패턴 ([Copier – Updating](https://copier.readthedocs.io/en/stable/updating/)):
- `copier update` → 최신 태그.
- `--vcs-ref=HEAD` → 태그 무시, default 브랜치 최신 commit.
- `--vcs-ref=<tag/commit/branch>` → 특정 ref.
- `--vcs-ref=:current:` → 템플릿 버전 유지, 답변만 갱신.

**롤백(다운그레이드)** — 별도 커맨드 없음. `--vcs-ref`에 더 낮은 태그/커밋을 지정해 그 버전으로 update한다. ⚠️ migrations는 `new version ≥ 선언 version > old version`에서만 실행되므로 다운그레이드 시 down-migration이 자동 실행되지 않는다 (마이그레이션 트리거 규칙에서 추론 — 문서에 롤백 시나리오로 명시되진 않음, flag).

**버전 태그 권장** — 태그는 안정 유지, 생성 후 이동 금지. 이동성 ref는 브랜치를 쓰거나 `--vcs-ref`로 명시 ([Generating – Templates versions](https://copier.readthedocs.io/en/stable/generating/)).

## 4. migrations (`_migrations`)

`copier.yml`의 `_migrations` 리스트에 정의하며 각 항목은 `command`/`version`/`when`/`working_directory` 키를 가진다 ([Configuring – migrations](https://copier.readthedocs.io/en/stable/configuring/)):

- `version` 지정 시 **new ≥ 선언 version > old**일 때만 실행, 이 경우 템플릿이 unsafe로 표시됨.
- **update 시에만** 실행(최초 copy 시 미실행). pre-migrations는 merge 전, post-migrations는 merge 후.
- 제공 변수: `$STAGE`(before/after), `$VERSION_FROM`, `$VERSION_TO`, `$VERSION_CURRENT` + PEP440 정규화판(`$VERSION_PEP440_*`, 변수 기반 마이그레이션에 권장).

작성 예시:
```yaml
_migrations:
  - invoke -r {{ _copier_conf.src_path }} -c migrations migrate $STAGE $VERSION_FROM $VERSION_TO
  - version: v1.0.0
    command: rm ./old-folder
    when: "{{ _stage == 'before' }}"
```

⚠️ **형식 버전 분기**: v9.3.0 이전은 구형식(dict with `before`/`after` 키)이며 지금도 동작하나 warning 발생 ([PR #1510](https://github.com/copier-org/copier/pull/1510)). 배포 대상 Copier 버전이 v9.3.0 이상이면 신형식.

## 5. 안전한 update 타이밍 + CI/자동화

**타이밍**: destination 폴더에서 `git status` clean 확인 후 실행 ([Copier – Updating](https://copier.readthedocs.io/en/stable/updating/); [copier-uv update.md](https://github.com/pawamoy/copier-uv/blob/master/docs/update.md)). dirty tree면 update diff/충돌과 미커밋 변경이 섞여 회복 곤란.

**권장 워크플로우 — 전용 브랜치 → 리뷰 → PR** ([Salt Extensions – Updating](https://salt-extensions.github.io/salt-extension-copier/topics/updating.html)):
```
git switch -c copier-update
copier update --trust
git status && git diff      # 충돌·변경 검토
git add . && pre-commit run -a
git commit -m "Update to template 0.4.2" && git push
```

**CI/자동화**:
- 업데이트 존재 체크: `copier check-update --output-format json` 또는 `--quiet`(exit 2 = 업데이트 있음) ([Copier – Checking for updates](https://copier.readthedocs.io/en/stable/updating/)).
- 비대화형: `copier update --trust --skip-answered --defaults` (특정 버전 고정 시 `--vcs-ref=X`). ⚠️ 새 질문 도입 시 기본값 사용 — 커스텀 답변 필요하면 수동 update ([Salt Extensions](https://salt-extensions.github.io/salt-extension-copier/topics/updating.html)).
- 봇: RenovateBot이 Copier update PR 지원(충돌 시 충돌째 PR + 경고). 자동 PR도 사람 리뷰 + CI 통과 후 머지 ([Salt Extensions](https://salt-extensions.github.io/salt-extension-copier/topics/updating.html)).

## Key Takeaways

- **E1-S5 게이트 = clean tree**: update는 반드시 `git status` clean에서 실행. 하네스의 "안전 타이밍(hub·clean tree·story 사이)" 요구와 정확히 일치 — story 경계에서만 update 실행하도록 게이트.
- **`.copier-answers.yml` 수동 편집 금지 + git tracked 필수**: D3(tracked) 결정과 정합. 이 파일이 SoT이므로 커밋 누락 시 update 파손.
- **롤백 = `--vcs-ref=<이전 tag>`**: 별도 롤백 명령 없음. 로드맵 "--vcs-ref 롤백"은 다운그레이드 update로 구현. down-migration 자동 미실행 리스크를 스펙 Open Question으로 명시.
- **충돌 커밋 방지 pre-commit 훅**: `check-merge-conflict --assume-in-merge`(inline) / `\.rej$` fail 훅(rej)을 배포 템플릿에 포함 검토.
- **migrations 형식은 Copier 버전 의존**: v9.3.0 경계로 신/구 형식 분기 — 배포 대상 Copier 버전 고정·명시 필요.
- **모노레포 `_src_path` 리스크(flag)**: tack이 `template/` 단일 템플릿 구조면 해당 없음. 다중 템플릿 확장 시 답변 파일 분리 필요.
